Free Palestine Bank — Queue Management Platform (SC-03)An intelligent, real-time token and queue optimization platform built for the SC-03 Public Service Queue and Wait-Time Optimizer challenge. Designed specifically for Free Palestine Bank, the platform eliminates long, unpredictable physical lines by combining a frictionless citizen experience with an optimized counter-staff workflow.🌟 Problem & SolutionThe Problem: Long and unpredictable wait times at bank and service counters waste citizens' time and create severe operational bottlenecks, as quick transactions get trapped behind lengthy service requests.The Solution: A digital token system where citizens can scan a QR code to view live wait times and request tokens instantly without logging in, while bankers utilize an optimized Shortest Job First (SJF) + Aging scheduling engine and a real-time operator command center.🧭 Pages & Route MapPageFileAccess LevelDescriptionLanding & QRindex.htmlPublicWelcome portal displaying a downloadable QR code that links straight to the public queue service portal.Service Request & Trackerservices.htmlPublicFrictionless citizen portal. Citizens / Customers (Frictionless)No Login Required: Customers scan the QR code on index.html or visit services.html.Token Generation: Enter full name, select a required banking service, and click "Continue".Live Tracking: The screen transforms into a live tracker showing people ahead, estimated wait time in minutes, and status badges. Users can cancel their token while waiting or being served.2. Counter Operators & Administrators (Secure)Authentication: Staff must log in via login.html. New operators are onboarded through register.html by admins.Service Configuration: Through jobs.html, operators establish service types and baseline durations (e.g., quick 1-minute deposits vs. multi-minute account setups).Queue Control: The operator dashboard (dashboard.html) auto-refreshes every 5 seconds, displaying real-time operational analytics and allowing staff to advance queue tokens smoothly.🧮 Queue Optimization: SJF + Aging AlgorithmTo prevent starvation of long-running tasks while maximizing counter throughput for quick transactions, the backend (BankQueueService) implements Shortest Job First (SJF) enhanced with dynamic aging:$$\text{Priority Score} = \text{Estimated Service Time} - (\text{Wait Time} \times 0.2)$$SJF Principle: Shorter tasks naturally float to the top of the queue to clear counter traffic fast.Aging Factor: As a customer waits longer in line, their score decreases based on their accumulated wait time multiplied by a 0.2 weight factor, ensuring absolute fairness.🛠️ Technology StackBackend: Java 17, Spring Boot, Spring Security, Spring Data JPA / Hibernate, REST APIs.Database: MySQL / H2 (Relational schema for tokens, jobs, and audit timestamps).Frontend: HTML5, Tailwind CSS, FontAwesome icons, Vanilla JavaScript (Fetch API, dynamic DOM manipulation, polling loops).Security & Session: Spring Security with role-based restrictions (ADMIN, STAFF) and permitted public static endpoints.⚠️ Known Limitations & Future ScopePassword Reset: The "Forgot Password" modal currently present on login.html is a frontend UI placeholder and is not functional yet (backend reset token services are planned for a future release).Multi-Counter Support: The current implementation uses a simulated single-counter model, with expansion for multi-counter allocation queued for subsequent iterations.🚀 Getting Started & Local SetupClone the repository:Bashgit clone https://github.com/Ahtisham-1214/OpenHack-FreePalestine.git
